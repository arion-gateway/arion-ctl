# Kubernetes conformance runner

`run.sh` runs the Gateway API and Inference Extension conformance suites against
the controller and proxy built from the local working trees, in a disposable
[kind](https://kind.sigs.k8s.io) cluster.

## One command

From the repository root:

```sh
apps/arion_k8s_controller/conformance/run.sh all
```

The first run takes about 15 to 20 minutes, most of it the proxy's Rust build;
later runs reuse the Docker build cache and the cluster. Both suites run even
when the first fails, a summary of their reports is printed at the end, and the
exit status is nonzero when either suite failed.

```sh
apps/arion_k8s_controller/conformance/run.sh summary   # print the report statistics again
apps/arion_k8s_controller/conformance/run.sh clean     # delete the kind cluster
```

## Prerequisites

| Tool | Notes |
| --- | --- |
| `docker` | Docker Desktop with WSL integration works |
| `kubectl` | any recent version |
| `kind` | `go install sigs.k8s.io/kind@latest` puts it in `~/go/bin` |
| `helm` | the [release tarball](https://get.helm.sh) into `~/.local/bin`, or a package |
| proxy source | the `arion` checkout beside this repository, or `ARION_PROXY_REPO=/path` |

The proxy image is built with the proxy repository's own `docker/Dockerfile`.

Give the Docker VM at least 4 GB of free memory: the controller, the proxy
data planes of the conformance Gateways and the runner Job share one node.

## What `all` does

1. `setup`: creates or reuses the kind cluster `arion-conformance` and makes it
   the current kubectl context; installs the Gateway API and Inference
   Extension CRDs; builds `arion-k8s-controller:conformance` and
   `arion-proxy:conformance` and loads them into the node; installs the chart
   from this tree as release `arion-ctl` in `arion-system`; restarts the
   controller onto the freshly loaded image (Helm sees no change when the tag
   is unchanged); runs `smoke.sh`, which routes one request through a
   provisioned data plane.
2. `gateway`: the Gateway API suite, profile `GATEWAY-HTTP` with the extended
   features the controller declares, as an in-cluster Job using `GO_IMAGE`.
3. `inference`: the Inference Extension suite, the same way.

Each suite's namespaces (`gateway-conformance-*`, `inference-conformance-*`)
are deleted before it starts, so an interrupted run cannot leave its Gateways
on an older proxy image. Each suite's log is copied from the Job's pod, so a
hung suite still reports.

## Reports

Each suite writes its log and its conformance report YAML to
`apps/arion_k8s_controller/conformance/reports/`, which is ignored by git: the
files are regenerated by every run and record the local `conformance` image
tags and the version `dev`. To submit a conformance claim upstream, run the
suites against the released images (`BUILD_IMAGES=false` with versioned
`CONTROLLER_IMAGE` and `ARION_IMAGE`, and `CONFORMANCE_VERSION` set to the
release) and commit that report deliberately.

## Overrides

| Variable | Default | Meaning |
| --- | --- | --- |
| `CLUSTER` | `arion-conformance` | kind cluster name (context `kind-<name>`) |
| `RUN_NAMESPACE` | `arion-conformance` | namespace of the runner Jobs |
| `GATEWAY_CLASS` | `arion` | GatewayClass the chart creates and the suites use |
| `GATEWAY_API_VERSION` | `v1.6.0` | Gateway API release: CRDs and suite |
| `INFERENCE_EXTENSION_VERSION` | `v1.5.0` | Inference Extension release: CRDs and suite |
| `GO_IMAGE` | `golang:1.26` | image the suites compile and run in |
| `CONTROLLER_IMAGE`, `ARION_IMAGE` | `...:conformance` | image references; versioned tags for published images |
| `ARION_PROXY_REPO` | `../arion` | proxy source tree to build the data-plane image from |
| `BUILD_IMAGES` | `true` | `false` uses or pulls the named images instead of building |
| `REPORT_DIR` | `conformance/reports` | where logs and reports are written |
| `CONFORMANCE_VERSION` | `dev` | implementation version recorded in the reports |
| `KUBECONFIG` | your default | set it to a temporary file to keep the kind context out of your kubeconfig |

## Expected results

Both suites pass in full: GATEWAY-HTTP core and extended (for the declared
features) and the Inference Extension suite.

The suite skips the extended tests of features the controller does not
declare, so the declared list, kept in `Arion.K8sController.Status.Conditions`
and in `run.sh`'s `--supported-features`, must match what the controller and
proxy do. Notable omissions:

- `HTTPRouteBackendRequestHeaderModification`: the controller rejects backend
  filters on a rule that splits traffic between several backends, which that
  feature's conformance test requires.
- `HTTPRouteRetry` and its two companions: retries are translated, but the
  features are experimental-channel and their `retry` field exists only in the
  experimental CRDs, which the runner does not install.
- `HTTPRouteHostRewrite`: hostname rewrites are not supported by the proxy.

Report the exact images, API versions and profile with any result; the suite's
report YAML records them.

## Troubleshooting

- `error getting credentials` while building images: Docker Desktop stores
  registry credentials in a Windows helper (`credsStore` in
  `~/.docker/config.json`) that a detached or non-interactive WSL shell cannot
  reach. Run from an interactive shell, or for public base images point
  `DOCKER_CONFIG` at a directory holding an empty `{}` `config.json`.
- The controller pods crash-loop with exit code 137 and empty logs: the pod was
  OOM-killed. Node runtimes that set the open-files limit near a billion make
  the Erlang VM reserve about 2 GB for its port table; the release caps
  `ERL_MAX_PORTS` at 65536, so check that the image is current.
- `kubectl` points at a dead `kind-arion-conformance` context after the cluster
  was removed outside the runner: `run.sh clean` then `run.sh all` recreates
  both the cluster and the context.
- A suite's base Gateways never become ready: look at the controller logs in
  `arion-system` for `reconcile failed` lines first; a resolver crash leaves
  every Gateway without status.
