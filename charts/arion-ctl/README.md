# arion-ctl Helm chart

[Project overview](../../README.md) ·
[Controller behavior and support](../../apps/arion_k8s_controller/README.md) ·
[Deployment options](../../docs/deployment-options.md)

This is the installation entry point for the Kubernetes controller. The chart
installs its Deployment, ServiceAccount, RBAC, ADS Service, peer-discovery
headless Service, Erlang cookie Secret, and optional GatewayClass. It also
includes the `ArionGatewayParameters` CRD.

Arion proxies are separate workloads. The controller provisions them when you
create Gateways, unless you select self-managed mode.

## Prerequisites

Use a Kubernetes cluster, kubectl configured for that cluster, Helm 3, and
controller/proxy images accessible to its nodes. The commands below run from
the arion-ctl repository root.

Install Gateway API CRDs **before** installing the chart. The project's
conformance runner pins Gateway API `v1.6.0` and Inference Extension `v1.5.0`;
these are project pins, not a recommendation to track upstream's newest release.

For standard Gateway/HTTP features:

```sh
kubectl apply --server-side -f https://github.com/kubernetes-sigs/gateway-api/releases/download/v1.6.0/standard-install.yaml
```

For stream-route features requiring the experimental bundle, use that bundle
instead:

```sh
kubectl apply --server-side -f https://github.com/kubernetes-sigs/gateway-api/releases/download/v1.6.0/experimental-install.yaml
```

For InferencePool support, also install the Inference Extension CRDs:

```sh
kubectl apply -k 'https://github.com/kubernetes-sigs/gateway-api-inference-extension/config/crd?ref=v1.5.0'
```

The watcher requests the versions listed in the
[controller support table](../../apps/arion_k8s_controller/README.md#supported-resources-and-features).
Unserved kinds/versions are treated as empty and rechecked every 30 seconds.
Installing a CRD does not enable an unimplemented traffic feature; UDP remains
unsupported.

Helm does not install or upgrade Gateway API/Inference Extension CRDs. It installs
the Arion CRD on first installation, but CRD schema upgrades must be applied
separately. Follow the upstream
[CRD guidance](https://gateway-api.sigs.k8s.io/guides/getting-started/introduction/)
for your chosen Gateway API version.

## Images and installation

The chart defaults are version-pinned:

- Controller: `ghcr.io/arion-gateway/arion-ctl-controller:0.1.0`
  (`image.tag` falls back to chart appVersion).
- Proxy: `ghcr.io/arion-gateway/arion:0.1.0`.

Confirm these artifacts are published and accessible before relying on them.
With available default images:

```sh
helm upgrade --install arion-ctl charts/arion-ctl \
  --namespace arion-system --create-namespace --wait
```

For your own compatible versioned images:

```sh
helm upgrade --install arion-ctl charts/arion-ctl \
  --namespace arion-system --create-namespace --wait \
  --set image.repository=registry.example/arion-ctl-controller \
  --set-string image.tag=0.1.0 \
  --set-string dataPlane.image=registry.example/arion:0.1.0
```

Replace the illustrative registry names with images you have built and pushed
or loaded into your local cluster. Build instructions are in
[development](../../docs/development.md#builds-and-integration-checks).
Local node-loaded images also need an appropriate pull policy.

After a versioned OCI chart has been published, it can replace the checkout path:

```sh
helm upgrade --install arion-ctl oci://ghcr.io/arion-gateway/charts/arion-ctl \
  --version 0.1.0 --namespace arion-system --create-namespace --wait
```

`imagePullSecrets` configures controller image credentials. Provisioned proxies
use their own ServiceAccounts; arrange proxy image access in the Gateway
namespace. `ArionGatewayParameters.spec.image` can override the proxy image
for a selected Gateway.

## Verify and provision a Gateway

With the release name and namespace above:

```sh
kubectl -n arion-system rollout status deployment/arion-ctl-controller
kubectl -n arion-system get pods,services
kubectl get gatewayclass arion -o yaml
kubectl -n arion-system logs deployment/arion-ctl-controller --tail=100
```

The default GatewayClass is `arion`, owned by
`arion.io/gateway-controller`. The controller's ADS service is
`arion-ctl-controller-ads`; its headless discovery service is
`arion-ctl-controller-headless`.

Apply the [Arion provisioning example](../../apps/arion_k8s_controller/README.md#provisioning-and-ariongatewayparameters)
to create a Gateway with explicit replica and Service settings:

```sh
kubectl apply -f docs/examples/kubernetes/parameters.yaml
kubectl -n default get deployment,service,serviceaccount,configmap gateway-default-edge
kubectl -n default get gateway edge -o yaml
```

The proxy command generated by the controller is
`/arion --with-envoy-bootstrap /etc/arion/bootstrap.json`.
The provisioning example creates no route/backend; use the official
[HTTP routing guide](https://gateway-api.sigs.k8s.io/guides/user-guides/http-routing/)
to attach routing configuration to the Gateway.

For a route that does not work, inspect Gateway/Route conditions,
`observedGeneration`, proxy logs, and the actual backend. Controller readiness
alone does not verify application traffic.

## Availability and cookie reuse

The chart defaults to two replicas with leader election enabled. Every replica
reconciles and serves xDS. A headless service discovers BEAM peers, and one elected
leader performs status/provisioning writes.

A replica binds ADS only after initial listing and publication. Its startup
probe allows five minutes; readiness and liveness use the ADS port. Check API
connectivity and RBAC if a replica never becomes ready.

All replicas must share the same Erlang cookie. The chart generates it once and
uses Helm `lookup` to reuse the existing Secret on upgrade. To manage the Secret
separately:

```sh
kubectl create namespace arion-system --dry-run=client -o yaml | kubectl apply -f -
kubectl -n arion-system create secret generic arion-cookie \
  --from-literal=cookie="$(openssl rand -hex 32)"
helm upgrade --install arion-ctl charts/arion-ctl \
  --namespace arion-system --create-namespace --wait \
  --set cookie.existingSecret=arion-cookie
```

The Secret must contain key `cookie`. Retain an externally managed Secret
across uninstalls if it must survive reinstall. Offline `helm template` cannot
look up cluster Secrets, so use `cookie.existingSecret` when stable GitOps renders
are required. Cookie rotation requires restarting all replicas together.

ADS is internal to the cluster. Allow port 50051 (or the configured ADS port)
from proxies to controllers, and private TCP ports 4369 and 9100 between
controller replicas for distribution and discovery.

## Values

The full values file is [values.yaml](values.yaml).

| Value | Default | Meaning |
| --- | --- | --- |
| `replicaCount` | `2` | Controller replicas |
| `image.repository` | `ghcr.io/arion-gateway/arion-ctl-controller` | Controller image |
| `image.tag` | Chart appVersion | Controller tag |
| `image.pullPolicy` | `IfNotPresent` | Controller pull policy |
| `imagePullSecrets` | `[]` | Controller registry credentials |
| `dataPlane.image` | `ghcr.io/arion-gateway/arion:0.1.0` | Default provisioned proxy image |
| `controllerName` | `arion.io/gateway-controller` | GatewayClass controller identity |
| `gatewayClass.create` / `gatewayClass.name` | `true` / `arion` | Chart-managed class |
| `leaderElection` | `true` | Cluster replicas and elect one writer |
| `cookie.existingSecret` | empty | Use chart-managed cookie unless a Secret name is provided |
| `controlPlanePort` | `50051` | ADS port |
| `resources.requests` | 100m CPU, 128Mi memory | Controller resource requests |
| `resources.limits` | 512Mi memory | Controller resource limits |
| `nodeSelector`, `tolerations`, `affinity` | empty | Controller scheduling |

Controller resource settings and replica count apply to the controller, not
provisioned proxies. Use ArionGatewayParameters for proxy settings.
Disabling leader election is intended for a single controller replica.

## Upgrade and uninstall

Before an upgrade, check controller/proxy compatibility and apply any changed
Arion CRD schema:

```sh
kubectl apply -f charts/arion-ctl/crds/ariongatewayparameters.yaml
helm upgrade --install arion-ctl charts/arion-ctl \
  --namespace arion-system --wait
```

Include the same image and external-cookie overrides used by your installation,
or keep them in a version-controlled Helm values file. Keep the existing cookie
unless you are intentionally rotating all replicas.

Remove the provisioning example before uninstalling if its Gateway is no longer
needed:

```sh
kubectl delete -f docs/examples/kubernetes/parameters.yaml
helm uninstall arion-ctl --namespace arion-system
```

Helm uninstall does not remove Gateway API CRDs, and Helm retains CRDs installed
from the chart's `crds/` directory. Gateways/proxy objects outside the chart
release have their own lifecycles; review them separately before removing shared
CRDs or namespaces.

The legacy Orion CRD/controller identities are not supported. Use Arion
GatewayClasses and ArionGatewayParameters when adopting this release.
